SESSION: Engine v3 Migration Batch 4 Part 2 (SQL Injection / XSS Detection)
===============================================================================
Phase: A8 Batch 4 Part 2 - migrate SQL Injection + XSS Detection to
evidence-only (higher detection accuracy priced over migration speed; LFI /
SSRF / SSTI / Open Redirect explicitly deferred to the final batch).

Scope (per spec): SQLi error/boolean/time techniques with structured evidence
(Payload, Request, Response, Parameter, Matched rule, Reliability, Weight,
Reproducibility, Timing, Fingerprint); XSS per-context evidence (reflected,
stored-when-observable, DOM indicators, context reflection) with
executable-context confirmation. No single-regex/single-payload confirmation.

Rewrites:
- scanners/sqli.py (use_engine_pipeline=True, evidence-only):
  * error_based  - per-DB signature (mysql/postgresql/mssql/oracle/sqlite) on
    the primary payload AND reproduced with a second distinct payload
    (alternate quote construction). Emits structured request_response evidence
    with matched_rule + database + reliability=high.
  * boolean_based - true/false responses differ by >=40 bytes, status, or <0.8
    Jaccard similarity (ResponseAnalyzer.body_similarity) AND reconfirmed with
    the independent comment-injection pair '/**/OR/**/1=1-- - vs
    '/**/AND/**/1=2-- -. Emits comparison metadata (lengths, statuses,
    similarity). reliability=medium.
  * time_based   - delay >= max(baseline+4, 6)s vs a 3-sample median baseline,
    AND a retry reproduces the delay (retry consistency + variance recorded).
    Emits timing metadata (baseline_latency, threshold, delay_latency,
    retry_latency, retry_variance). reliability=high.
  * Observations deduped per parameter; every confirmed observation carries
    verification_pass=2 ("primary + confirm payloads"). 2+ techniques on the
    same parameter add a cross_validation (verified) evidence. Fingerprint
    sqli_signals[] + database. Clean / no-params emit a verified no-finding
    evidence (tests_passed=0 for no-params preserves v2 pass/none/75/verified/
    not_applicable parity).
- scanners/xss.py (use_engine_pipeline=True, evidence-only):
  * Three families (html / attribute / javascript), each tested per parameter
    with a primary payload AND reconfirmed with a second distinct payload plus
    an independent context regex (no single-regex confirmation).
  * Context regexes are executable-location-precise: the marker (alert() or
    handler token) must sit inside the SAME tag/script that the payload broke
    into (e.g. '<script[^>]*>\s*alert\('), so a page that merely echoes
    HTML-escaped input ('&lt;script&gt;') never matches. Attribute context
    requires a literal quote breakout / unquoted injection - escaped '&quot;'
    / '&gt;' cannot trip it (fixes a false-positive vector where loose
    \sonerror= / \sonfocus= patterns fired on escaped output).
  * 2+ contexts on the same parameter add cross_validation (verified)
    evidence. Encoded-probe decoding is 'likely' SUPPORT evidence emitted only
    alongside a confirmed core context (never a standalone finding, and never
    'possible' - the evidence-level cap chain would cap confidence at 60).
    Fingerprint xss_signals[] + reflected_params. Clean / no-params emit a
    verified no-finding evidence.

Behavioural changes (all explained):
- Single-technique SQLi now verifies as 'likely' (conf ~80) instead of the old
  v2 'verified'; 2+ techniques on the same parameter ('verified') are the only

- SQLi no-params emits verified evidence + tests_passed=0 (NOT bare f.skipped)

  (bare f.skipped produced v2 none vs v3 info).
- XSS event-handler patterns no longer fire on escaped/echoed output (tightened
  to prove executable delivery), removing a false-positive vector.

  * disclosure     - >=2 distinct sensitive-file markers on independent payloads.
  * os_fingerprint - POSIX vs Windows file markers on two distinct files.
  * null_byte      - a '%00' payload discloses a file the plain path does not

  * Adaptive depth _guess_depth() (3-8). Fingerprint lfi_signals[] +
    files_disclosed. 2+ techniques add cross_validation (verified) evidence.

  * metadata         - cloud metadata markers (169.254.169.254 / Google
    computeMetadata) return through the parameter, reproduced on a second
    metadata endpoint.
  * internal_access  - response to a private address differs from baseline
    (>500 bytes or status), reproduced on a second address.
  * error_signature  - URL-fetch error strings (Connection refused, DNS
    failures) reproduced twice.
  * redirect         - server follows a payload URL that redirects to an
    internal/attacker target (observed without following).
  * oast             - out-of-band interaction when an OAIST manager is
    configured (never a hard failure without one).
  * Fingerprint ssrf_signals[]. 2+ techniques add cross_validation evidence.
- scanners/open_redirect.py (Open Redirect):
  * absolute / relative / protocol_relative / encoded / double_encoding

    open_redirect_signals[]. 2+ techniques add cross_validation evidence.

    expressions evaluate to the expected results ({{7*7}}->49 AND {{8*9}}->72),
    ruling out numbers already present in the page. '{{ expr }}' syntax
